# 见账账号同步 · 配置教程

当前仓库公开发布软件源代码。**账号登录功能必须由你先创建自己的 Supabase 项目，配置完成后才会激活。** 不要共享任何用户密码、数据库口令或 service_role/secret API key。

## 一、创建云端服务

1. 打开 https://supabase.com/dashboard ，注册并创建一个 Project。
2. 在 SQL Editor 执行本仓库的 [supabase.sql](./supabase.sql)；确认表 public.jianzhang_ledgers 的 RLS 已开启。
3. 在 Authentication → Providers 中启用 Email。建议开启邮箱确认（需配置发信服务、站点 URL）。
4. 在 Project Settings/API Keys 获取 **Project URL** 和 **publishable key**（或者原有的公开 anon key）。
5. 修改项目根目录的 cloud-config.js，仅填写上述两个公开值。**严禁填写 service_role、secret key 或数据库密码**。
6. GitHub Pages 会自动发布网页；APK 需要重新执行 Android APK 构建才会内置新的配置。
7. 分别在安卓、iPhone Safari 和电脑上使用同一个邮箱登录。首次登录选择使用云端账本或上传本机账本。

## 二、数据同步规则（重要）

- 没有登录或未配置时，继续使用纯本机账本。
- 登录后先检查云端与本机。两者不同时**不会直接覆盖**，需选择云端或本机，并建议先导出 JSON 备份。
- 修改先保存本机，然后尝试异步上传。无网络时本机仍可记账，重连后重试。
- 云端使用 revision 版本条件更新；若另一设备抢先修改，会暂停自动上传并提示冲突，而不是静默丢掉改动。
- 每 30 秒在页面可见时检查云端变动，恢复窗口也检查。**不是毫秒级实时同步**。
- 不同登录账号使用不同的本地存储隔离；退出登录会显示游客账本。
- 账户登出并不自动擦除该账号的本地缓存：私人设备应设置系统锁屏密码，不要在公共设备使用。
- 应用数据存储在 Supabase 云数据库。**目前未做客户端端到端加密**，不能承诺云端服务管理员看不到账本。
- 原有游客账本不会自动归入任何用户账号。需要先导出 JSON，再登录账号并手动导入、上传。

## 三、检测与验收

1. 手机 A 登录，选择「上传本机账本」，记录 1 笔小额测试支出。
2. 手机 B 用同一账号登录，选择「使用云端账本」，看是否有该笔流水。
3. 手机 B 添加新账，等待同步后在手机 A 刷新/切回应用，检查总账。
4. 分别断网新增两笔记录再重连，检查是否出现冲突提示，避免自动覆盖。
5. 使用另一个账号登录，确认无法读取第一个账号的数据。
6. 分别导出 JSON，并做恢复演练。

## 四、进一步安全建议

- 生产环境使用专业身份认证 SDK、邮箱防滥用与有效的邮件服务。
- 数据传输使用 HTTPS；不在 GitHub 仓库、工单或聊天中分享用户密码、服务端密钥。
- 这个 V1.1 是客户端同步接入版本，不建议直接存放没有单独备份的唯一财务资料。
- 如未来要做家庭共享，应另外设计共享权限模型（多人共同账号不推荐）。
